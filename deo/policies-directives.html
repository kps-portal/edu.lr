What this page shows

Every row is read and written from memos (title, category, priority, audience, audience_detail, date_issued, effective_date, review_date, body, pinned, issued_by_name, issued_by_title) — the single shared notices table also used by principal/memos.html for school-level announcements and read by the DEO dashboard, registrar and other principal screens as a pinned-notice ticker. A directive issued here and a memo issued by a principal appear together in the same feed, since the table carries no institution or issuer-role column to separate them.

Reference codes (e.g. DIR-4F21A9) are derived client-side from each record's own database id, not a stored field, so they're always consistent with the live row.

Status (Scheduled / In Effect / Review Overdue) is computed from the real effective_date and review_date columns rather than a stored status field, which this table does not have.

Write access to memos was previously limited to the principal and super_admin roles; a small RLS policy change (see supabase/migrations/007_allow_deo_write_memos.sql) added deo so this page can issue and withdraw district-wide directives. That policy is role-based, not owner-based, so — consistent with how principal/memos.html already behaved — any of the three roles can edit or withdraw any row, not only the ones they issued.

DEO can: issue a district-wide policy, circular or directive; pin an urgent notice to the shared notice board; toggle or withdraw a directive; search/filter/sort the register; and export it to CSV.
