Scope of Access & How This Report Is Saved
There is no dedicated reports table anywhere in this schema (checked every .from('...') call in the codebase). This page saves what you type through KPS.kv — a real Supabase-backed key/value bridge (kv_store table), the same one already used for genuine persistence by annual-report.html, quarterly-report.html, special-report.html, and several Super Admin settings pages. Each month's report is one JSON record, private to your account (shared:false) until you choose to finalize it. "Finalize Report" marks status only — there is no external delivery role or working notification schema yet to actually deliver it; see "What this page shows".

What this page shows

Storage — each month's report is one JSON record in the real kv_store table, keyed deo_monthly_report:<year>-M<01-12> and scoped private (shared:false) to your own account. Nothing is stored only in your browser — it survives refresh and device changes.

Month picker — covers the current month plus the eleven before it (one year back), defaulting to whichever month contains today's date. Switching months loads that month's own saved record.

Save draft vs. Finalize Report — both write to the same record. Submitting sets status: 'submitted' and stamps submittedAt, but does not notify any external account or route anywhere: there is no external delivery role defined in this codebase yet, and the notifications table's columns are inconsistent across the two places that already read it. A future pass can wire real delivery once those exist.

No figures on this page are pulled automatically from other tables (e.g. attendance, assessments, staffing records) — every field is free-text entered by you, matching how the original report form worked. Automated evidence pulls would be a real feature to add later, not something to fake here.

DEO can: draft, save, and submit the monthly operational report for any of the last 12 months, entirely within their own private account — real persistence, not a demo.
